FOR DEVELOPERS

Pair once, then keep secrets out of source.

Browser clients are bound to one exact origin. Local Node.js clients use a separate token type that browsers cannot replay.

LOCAL NODE.JS

Create a short-lived client

01

Run this in PowerShell. The token is shown once and is not copied here.

printlatch clients create --name "Invoice worker" --days 30
import { PrintLatch } from "@printlatch/sdk";

const client = new PrintLatch({
  token: process.env.PRINTLATCH_TOKEN,
});

const preview = await client.createJob({
  pdf,
  mode: "preview",
});

WEB APP

Bind an exact origin

02

Create a five-minute code locally. Paste it only into the web app named in the command. 

printlatch pair --origin https://app.example --name "Invoice app"
Why two token types?

A browser token must carry the exact paired Origin header. A local-process token is rejected if a browser Origin header is present.

ABOUT

A narrow local bridge, not a universal print server.

PrintLatch 0.1 supports static, unencrypted PDFs on its verified Windows 11 x64 path. Raw label commands, fleet management, cloud relay, macOS, and Linux are outside this release.
